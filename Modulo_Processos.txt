2. Introdução
2.1.

Objetivos do documento

Pretende-se com este documento descrever, de forma clara e objetiva, as interfaces a
implementar e os requisitos funcionais do módulo para gestão de processos e sub processos
no portal de gestão da qualidade.
Este documento deverá ser revisto, validado e aprovado pela entidade competente, à qual
compete verificar o cumprimento dos requisitos pretendidos para o módulo a implementar,
nomeadamente as funcionalidades a disponibilizar, assim como o comportamento dos vários
elementos apresentados nas diferentes interfaces do módulo.

2.2.

Objetivos do módulo

2.2.1. Componentes principais do módulo
Gestão de Processos:
•

Criação e edição de processos;

•

Criação e edição de sub processos, associados a um processo pai;

•

Associação de documentos a processos e sub processos;

•

Consulta de processos, sub processos e respetivos documentos;

•

Gestão de revisões dos processos e sub processos;

•

Consulta de histórico de processos e sub processos;

Gestão de Documentos:
•

Associação de documentos a processos e sub processos;

•

Classificação de documentos por tipo (Instrumento, Regulamento, Orientação,
Impresso);

•

Upload de ficheiros com validação de formato autorizado;

•

Registo de versão e data de elaboração;

•

Gestão de revisões de documentos;

•

Consulta de histórico de documentos;

Gestão de Tipos de Documento e Formatos:
•

Definição dos tipos de documento disponíveis;

•

Definição dos formatos de ficheiro aceites (ex.: PDF, XLS, XLSX, DOC, DOCX);

2.2.2. Descrição do módulo
Este módulo será disponibilizado no portal de gestão da qualidade e permitirá a gestão
centralizada de processos e sub processos, bem como dos documentos que lhes estão
associados. O acesso será feito por utilizadores com perfil de administração, atribuído por
serviço.

Cada processo poderá ter associado um ou mais sub processos, e cada sub processo
estará obrigatoriamente associado a um único processo pai. Tanto os processos como
os sub processos poderão ter documentos associados, classificados por tipo e sujeitos
a validação de formato.
O módulo deverá permitir a consulta de toda a informação, independentemente do estado em
que se encontre, bem como a gestão de revisões dos processos e sub processos.

3. Requisitos específicos
Gestão de Processos
O módulo deverá implementar mecanismos e funcionalidades que permitam a criação, edição
e consulta de processos. Cada processo deverá conter, a seguinte informação:
•

Código;

•

Nome ;

•

Data Revisão ;

•

Versão;

•

Objetivo;

•

Âmbito;

•

Data de elaboração;

•

Dono do processo (serviço / UO);

•

Documentos associados (em formato autorizado);

Deverá ser possível gerir revisões dos processos, mantendo o histórico de alterações.
Gestão de Sub processos
O módulo deverá permitir a criação de sub processos, os quais estarão obrigatoriamente
associados a um processo pai. Cada sub processo deverá conter os mesmos campos de um
processo, acrescidos da referência ao processo pai.
Deverá ser possível selecionar o processo pai a partir de uma lista de processos existentes.
Gestão de Documentos
O módulo deverá permitir a associação de documentos a processos e sub processos. Cada
documento deverá conter:


Código;



Nome do Documento;



Designação;



Versão;



Data de elaboração;



Tipo (Instrumento, Regulamento, Orientação, Impresso);



Ficheiros (1 input / uploads com validação por formato previamente definido);

Consulta de Processos e Sub Processos

4. Requisitos funcionais
4.1.

Gestão dos processos

A interface [I1] para a gestão dos processos deverá permitir filtrar, criar e editar processos. Os
critérios de filtragem são os campos definidos para o processo:


Código;



Nome ;



Objetivo;



Âmbito;

A pesquisa é um input único que percorre os campos definidos por peso, devolvendo registos
únicos por ordem de peso (ex. Códigos → Nomes → Objetivo → Âmbito).

[I1] Interface 1 – Lista de Processos
Nesta interface deverá ser possível consultar os processos existentes, mediante um conjunto
de critérios de pesquisa, bem como criar novos processos. A ordem do resultado de pesquisa
será alfabética dentro dos pesos já identificados sendo Código, Nome, Objetivo e por fim
Âmbito. A tabela [I1.TB01] terá também a possibilidade de alterar esta ordem em cada coluna,
ao clicar, os pesos deixam de estar em efeito passando só a ordem da coluna selecionada. A
ordem é acumulativa, o que cruza com a ordem das colunas selecionadas.
[I1.TXT01] Input Pesquisa
Campo de texto que permite pesquisar processos pelo seu código, Nome, Objetivo e Âmbito.
[I1.BT01] Pesquisar
Ao clicar no botão [I1.BT01] deverá ser realizada a pesquisa de processos de acordo com os
critérios indicados no campo [I1.TXT01].
Caso existam registos para apresentar, os mesmos devem ser apresentados de acordo com a
tabela [I1.TB01].

A interface [I5] para a gestão dos sub processos deverá permitir filtrar, criar e editar sub
processos associados a um processo pai. Os critérios de filtragem são os campos definidos para
o sub processo:


Código do processo Pai;



Código do sub processo;



Nome;



Objetivo;



Âmbito;

A pesquisa é uma união do input [I5.LB01] com os critérios do input [I5.TXT01] que percorre
os campos definidos por peso, devolvendo registos únicos por ordem de peso.

[I5] Interface 5 – Lista de Sub processos
Nesta interface deverá ser possível consultar os sub processos associados a um processo,
mediante um conjunto de critérios de pesquisa, bem como criar novos sub processos.
A ordem do resultado de pesquisa será alfabética dentro dos pesos já identificados sendo
Código do processo Pai, Código do sub processo, Nome, Objetivo e por fim Âmbito. A tabela
[I5.TB01] terá também a possibilidade de alterar esta ordem em cada coluna, ao clicar, os
pesos deixam de estar em efeito passando só a ordem da coluna selecionada. A ordem é
acumulativa, o que cruza com a ordem das colunas selecionadas.
[I5.LB01] Código Processo Pai
Apresenta a lista dos processos existentes, ordenada por ordem alfabética crescente do nome
com possibilidade de escrita.

[I13] Interface 13 – Detalhe Histórico de Processo
Nesta interface é apresentada a informação detalhada de uma versão anterior (histórica) do
processo. Sendo um registo histórico, o modo é de estrita observação, pelo que todos os
campos são apresentados num formato de leitura e são imutáveis.
[I13.TXT01] a [I13.DT02] Campos de Informação do Processo
Todos os campos descritivos do processo (Código, Nome, Objetivo, Âmbito, Data de
Elaboração, Versão e Data de Revisão) correspondentes à versão selecionada. Campos
imutáveis.
[I13.TB01] Tabela de Donos do Processo
Tabela com os utilizadores responsáveis pelo processo no momento em que esta versão estava
ativa. Colunas apresentadas: Nome, Email. Campo imutável.
[I13.TB02] Tabela com a lista de sub processos

• Código do sub processo;
• Nome;
• Versão;
• Data de elaboração. Associado a cada sub processo deve ser disponibilizado o botão de
ação: Detalhe [I13.TB02.BT01].
